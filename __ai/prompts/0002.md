# Task: Add live GitLab, Jira and OpenProject adapters to devzy

## Objective

Add **live** adapters for three providers to the `devzy` CLI (Bun + strict
TypeScript):

| Type          | Category | Today                    | After this task               |
| ------------- | -------- | ------------------------ | ----------------------------- |
| `gitlab`      | git      | mock adapter only        | mock + **live** (REST API v4) |
| `jira`        | tasks    | mock adapter only        | mock + **live** (Cloud REST v3) |
| `openproject` | tasks    | known, no adapter at all | **live** (API v3)             |

GitHub (mock + live) must keep working exactly as it does now. Its live adapter
is the reference implementation.

This is an implementation task: write the code, tests and docs, then run the
quality checks. Proceed without asking for approval. Stop only for a genuine
blocker, and in that case finish all independent work first.

## 1. What already exists (read these first)

The current code is the source of truth. Read it before changing anything,
then write a short plan.

- **Adapter contract.** `src/services/providers/adapter.ts`
  (`AdapterDefinition`, `AdapterContext`, `SetupField`, `CredentialSpec`).
  Adapters are registered in `BUILT_IN_ADAPTERS` in
  `src/services/providers/registry.ts`. Nothing else needs to know about a
  new adapter; commands, aggregation, `providers list/add` and `health` read
  the registry.
- **Reference live adapter.** `src/services/providers/git/github.provider.ts`.
  Copy its patterns:
  - a zod options schema;
  - zod validation of API responses;
  - a per-request timeout combined with the caller's `AbortSignal`;
  - refusing to follow a pagination link to another origin;
  - error messages built from status codes, never from response bodies;
  - a page cap that rejects with an error instead of truncating;
  - a local re-check of the half-open period.

  Its tests in `src/tests/unit/github-live.test.ts` show the stubbed-`fetch`
  style to reuse.
- **Interfaces.**
  - `GitProvider.getCommitStats(query)` returns one row per
    (repository, contributor). `query.repositories` holds lowercased repo
    filters to push down.
  - `TaskProvider.getUserTaskStats(query)` returns `{ users, unmappedStatuses }`.
  - Health checks are an optional `HealthCheckable` capability.
- **Task normalization.** `summarizeTaskEvents` and `StatusMapping` live in
  `src/domain/tasks.ts`. The static tables are in
  `src/services/providers/tasks/status-maps.ts`. Unmapped statuses are
  reported, never counted.
- **Credentials.** `registry.resolveCredential` resolves one secret per
  instance, in this order:
  1. `credentials.tokenEnv`;
  2. the type's `defaultEnv`, only when there is exactly one live instance of
     that type;
  3. `credentials.token` from the file.

  All output is redacted through `Logger`/`Redactor`.
- **Config.** `src/services/config/schema.ts` and `load.ts`. Adapter
  `options` are validated by the adapter's own schema. Unknown keys are
  rejected.
- **Reporting rules that must not change.** Read
  `services/aggregation.ts`, `filtering.ts` and `identity-resolver.ts`:
  - periods are inclusive UTC days, stored as `[since, until)`;
  - `--email` is matched after identity resolution, and rows without email
    data are excluded and noted;
  - failed providers produce partial reports with exit code 3 and are never
    shown as zero activity;
  - mock and live providers cannot be mixed without `--allow-mixed-modes`.

### Known gaps you must close

1. `SetupField.flag` only allows `"repo" | "base-url"` and `kind` only
   `"list" | "url"`. `providers add` needs new flags (at least `--project`
   and `--account-email`) and a plain `string` kind.
2. `CredentialSpec` covers a single token. Jira Cloud uses Basic auth with
   `email:api_token`. Keep the **email as a non-secret option**
   (`options.email`) and the API token as the credential.
3. Status mappings are hard-coded. Add an optional, validated
   `options.statusMap` (`{ "<vendor status>": "completed" | "in_progress" |
   "in_review" }`) to the live Jira and OpenProject adapters. It is merged
   over the built-in defaults, and lookups are case-insensitive. Existing
   configs stay valid.
4. HTTP plumbing is private to the GitHub adapter. Extract a small shared
   helper (for example `src/services/providers/http.ts`) for:
   - timeouts and signal combining;
   - same-origin URL checks;
   - mapping status codes to `ProviderHttpError` kinds (auth, permission,
     not found, rate limit, server, network, timeout).

   Use it in the three new adapters. Move GitHub onto it **only if**
   `github-live.test.ts` passes unchanged. Otherwise leave GitHub alone.
5. Spawned CLI tests (`spawnCli`) cannot stub `fetch`. Test live providers
   end-to-end in-process with `runInProcess(..., { deps: { fetch } })` from
   `src/tests/helpers.ts`.

## 2. Shared rules for all three adapters

- **Count the same things as the existing contract.**
  - Git: commits in the period, one row per (project, author).
  - Tasks: tasks assigned to a person whose status last changed within the
    period, bucketed by their *current* normalized status.

  Document the vendor field used for "status last changed" and any
  approximation (see Jira below). Never count every issue a search returns
  as completed.
- **Identity.**
  - Fill `providerUserId` and `username` whenever the API exposes them.
  - Fill `email` only when the API returns it.
  - Never fetch users one by one to find emails.
  - Explicit `identities[].accounts` mappings are how users link Jira and
    OpenProject accounts that have hidden emails. Say so in the README.
- **Filters.**
  - `--repo` is pushed down to GitLab and only ever narrows the configured
    projects.
  - `--status` and `--email` stay local, as today.
  - Do not add new CLI filters.
- **Reliability.**
  - Every request uses `settings.requestTimeoutMs` and the caller's signal.
  - Use bulk list endpoints with the maximum page size.
  - Each adapter has a page cap constant, and exceeding it is an error.
  - Retry only HTTP 429 and 502/503/504, at most 2 times. Use `Retry-After`
    (capped at 10 s) or a 500 ms/1 s backoff. Inject the sleep function so
    tests never wait.
  - Never fall back to mock data.
- **Security.**
  - Base URLs must be http(s) with no embedded credentials, as with
    GitHub's `baseUrl`.
  - Tokens are sent only to the configured origin.
  - Response bodies are never echoed.
  - Every error is tested to contain no token.
- **Health.** Each adapter implements `HealthCheckable`: it authenticates and
  confirms access to every configured project, as GitHub does.
- **Credential defaults.**

  | Type        | `defaultEnv`          |
  | ----------- | --------------------- |
  | gitlab      | `GITLAB_TOKEN`        |
  | jira        | `JIRA_API_TOKEN`      |
  | openproject | `OPENPROJECT_API_KEY` |

  The registry's "single live instance only" rule applies unchanged.
- **Mocks.** Keep the existing GitLab and Jira mock adapters and the built-in
  demo configuration unchanged. Adding an OpenProject mock adapter is
  optional. If you add one, follow the existing mock fixture conventions and
  tests.

Verify every endpoint, parameter, header and response field below against
the official documentation before relying on it. If the docs differ from
this prompt, follow the docs and note the difference in your final summary.

## 3. GitLab (live)

- **Options.**
  - `baseUrl`: default `https://gitlab.com`. The adapter appends `/api/v4`,
    which also covers self-managed instances, including ones under a
    sub-path.
  - `projects`: required list of full project paths. Nested groups such as
    `group/sub/project` are allowed.
- **Auth.** `PRIVATE-TOKEN` header (or `Authorization: Bearer`; pick one and
  test it). Minimum scope: `read_api`, or `read_repository` plus `read_api`
  for health. Document it.
- **Commits.** `GET /projects/:url-encoded-path/repository/commits` with
  `since`, `until`, `per_page=100`, using the default branch like GitHub.
  - Paginate with `x-next-page`, or the `Link` header with the same-origin
    check.
  - Count by `committed_date` within `[since, until)`.
  - Map `author_name` and `author_email`.
  - GitLab commits carry no user ID; leave `providerUserId` unset rather than
    guessing.
- **Edge cases.** Empty repository or no default branch gives zero rows, not
  an error. 401, 403 and 404 give clear per-project messages.
- **Health.** `GET /user`, then `GET /projects/:path` for each project.

## 4. Jira Cloud (live)

- **Options.**
  - `baseUrl`, for example `https://your-site.atlassian.net`.
  - `email`: the Atlassian account email used for Basic auth. It is not a
    secret, but never print it combined with the token.
  - `projects`: required list of project keys.
  - Optional `jql`: an extra clause combined with `AND`.
  - Optional `statusMap`.
- **Auth.** `Authorization: Basic base64(email:token)`. Document that the API
  token comes from id.atlassian.com and needs "Browse projects" permission.
- **Search.** Use the enhanced search endpoint
  (`GET`/`POST /rest/api/3/search/jql`) with `nextPageToken` pagination. The
  legacy `/rest/api/3/search` is deprecated; do not depend on it.
  - Request only the needed fields: `assignee`, `status`,
    `statuscategorychangedate`, `updated`.
  - Build JQL from the project keys and period, with dates formatted for JQL
    and the timezone handled explicitly. Re-check the period locally.
- **"Status last changed".** Prefer `statuscategorychangedate`, and fall back
  to `updated`. Category dates miss transitions within one category (for
  example In Progress to In Review). Document that limitation. Do not fetch
  per-issue changelogs.
- **Identity.**
  - `assignee.accountId` maps to `providerUserId`.
  - `emailAddress` is often hidden; leave it undefined in that case.
  - Unassigned issues are excluded and counted in a report note. Add the note
    through the existing `unmappedStatuses` mechanism or a minimal, tested
    extension.
- **Status mapping.** Default to `JIRA_STATUS_MAP` merged with
  `options.statusMap`. Unknown statuses are reported as unmapped. Do not map
  by `statusCategory` automatically: "Done" can mean "Won't do".
- **Health.** `GET /rest/api/3/myself`, then `GET /rest/api/3/project/{key}`
  for each project.

## 5. OpenProject (live)

- **Options.**
  - `baseUrl`; the adapter appends `/api/v3`.
  - `projects`: required list of project identifiers or numeric IDs.
  - Optional `statusMap`. Default statuses: Closed and Resolved map to
    completed, In progress to in_progress, In testing / In review to
    in_review. Verify these against OpenProject's default workflow.
- **Auth.** Basic auth with user `apikey` and the API token as the password.
  Document where users create the token and which permissions it needs
  ("View work packages").
- **Work packages.** `GET /api/v3/projects/{id}/work_packages`, with a
  `filters` JSON parameter on `updatedAt` for the period and `pageSize` at
  the instance maximum.
  - Paginate by `offset` (it is a page number in OpenProject; verify this).
  - Parse HAL `_embedded.elements`. The status comes from
    `_links.status.title`. The assignee comes from `_links.assignee`: take
    the ID from its `href` and the display name from its `title`.
  - Use `updatedAt` as the "status last changed" approximation and document
    it.
- **Identity.** Emails are usually not exposed, so use user IDs. Placeholder
  users and groups as assignees are excluded and noted.
- **Health.** `GET /api/v3/users/me`, then `GET /api/v3/projects/{id}` for
  each project.

## 6. Setup flow (`devzy providers add`)

- Interactive mode asks only for the selected adapter's fields:
  - GitLab: projects, base URL, token env var.
  - Jira: base URL, account email, project keys, token env var.
  - OpenProject: base URL, projects, token env var.
- Non-interactive equivalents: `--base-url`, `--project` (repeatable),
  `--account-email` and `--token-env`. Report missing values exactly as the
  command does today.
- `statusMap` and `jql` are file-only settings. Document them; don't prompt
  for them.
- Tokens are never written; only the env var name is saved, as for GitHub.
- `providers list` must show `mock + live` for gitlab and jira and
  `live only` for openproject (or `mock + live` if you added the mock).
